## 对话数据同步到远程（21:30-23:00）

- 新增 `scripts/sync-data.sh`（把本机 ~/.dsh 会话+批注同步到远端部署实例，先备份、停服务、合并 workspace.json）、`scripts/register-workspace.mjs`（注册兼容工作区，源路径 base64 传参防 shell 转换）、`scripts/rewrite-session-cwd.ts` + `scripts/sync-finalize.ts`（放到远端 session-persistence-jsonl 包目录内用 tsx 跑）。
- 关键机制（packages/workspace/workspace/src）：会话归属工作区要求 header.cwd 经 realpath 解析后与 workspace.path 严格相等；'D:/harness' 在 Linux 非绝对路径直接拒 → 同步来的会话一律被过滤，且 registry 在 attach 时按 candidateMatches 投影重写（静默剪枝）。唯一干净解法：改写会话日志 header 的 cwd 为远端工作区路径。
- 会话日志格式：多帧 zstd（每帧独立可解），**第一帧必须恰好只含 header 行**（读取端 assertFirstFrameIsHeader）——把全部内容压成单帧会被判 corrupt 且静默从 list() 消失。重写只动第一帧、其余帧字节原样保留。
- zstd 解码器（NodePrivateZstdFrameDecoder）返回**内部暂存视图，下一次调用即失效**——收集引用再统一读取会全部变成最后一帧内容（曾据此误判"帧内有二进制前缀"）。必须逐块立即 Buffer.from 拷贝。
- 本地 13 个会话中 7 个是 session.jsonl.zstd（format v0），本构建无升级路径（"ships no upgrade path"）根本读不了 → 归档到远端 DSH_HOME/v0-legacy-sessions/。6 个 v4 会话重写 cwd 后全部可读、UI 列表可见、打开后内容完整（19265/4451 字符），标题由 session-title-llm 打开时自动生成。
