## 批注功能两处 bug 修复（同日）

- **bug：点"解释"报 `cannot get property "remote" without inject`** — 客户端插件 inject 数组写成了 `'remote.annotations'`；正确写法是注入 `'remote'`（整个 proxy，参照 cot-translation 的 `inject = ['remote', ...]`），然后 `ctx.remote.annotations.generate(...)`。
- **bug（终版修复）：点"提问/解释"报 `cannot get property "remote.annotations" without inject`** — 上面那条"修复"只对了一半。真实机制：gateway 客户端（`packages/api/gateway/src/client/index.ts`）把每个 remote 命名空间安装为**独立的点分 Cordis 服务**（`remoteServiceKey(namespace)` → `remote.<namespace>`，每命名空间一个 plugin）。消费方必须**同时**注入 `'remote'` 和 `'remote.<namespace>'` 两项（见 ui-reference：`inject: [..., 'remote', 'remote.fileReferences']`），访问 `ctx.remote.<ns>.method(...)`。只注入 `'remote'` 时，`ctx.remote` 可取但命名空间属性按点分服务解析 → 报 `cannot get property "remote.annotations" without inject`；只注入 `'remote.annotations'` 时，`ctx.remote` 这一步就失败。终版：`inject = [..., 'remote', 'remote.annotations']`。
- **测试桩模式（点分服务名）**：jsdom 测试里要 `class RemoteService extends Service { constructor(c){ super(c, 'remote') } }` + `new RemoteService(ctx)`，再 `ctx.provide('remote.annotations', { generate } as never)`（见 ui-reference 的 browser-plugin spec）；直接 `ctx.provide('remote', { annotations: {...} })` 在插件注入点分名后无法解除 park，插件不加载。
- **bug：点"提问"输入框不出现** — 根因：`wrapSelection` 包裹选区会改动 DOM，对话浮层（ui-chat `text-interaction.ts`）检测到选区失配立即 dismiss 卸载组件，React 状态里的提问表单随之消失。修复：提问输入框改为**独立原生 DOM 弹层**（`annotation-dom.ts` 的 `openAskPopover`，append 到 body，样式用 `--dsw-*` 设计变量），完全脱离浮层生命周期；Enter 提交 / Escape 或点外部取消（取消会 unwrap 锚点）。
- 新增端到端客户端测试 `tests/annotations.client.spec.tsx`（3 用例：提问提交全链路、Escape 取消、解释直达），连同原有用例 21 个全过。注意：原生 DOM input 触发要用 `fireEvent.input`（监听 input 事件，非 change）。
- `browser-plugin.client.spec.tsx` 夹具需为新注入服务补桩：`ctx.provide('sidebarRightTabs'/'sidebarRight'/'remote', {...} as never)`（参照 file-upload 测试）。
- Windows 下 session-controller 的 media-references 测试与 liveshare 的 readonly-fork 测试因符号链接 EPERM 失败（需开发者模式/管理员），属环境限制，与代码无关。
- jsdom 无 `Range.getBoundingClientRect`，取选区 rect 需 try/catch 兜底；避免 `new DOMRect`（用字面量 cast）。
