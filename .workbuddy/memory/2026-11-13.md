# 2026-11-13

## 启动 Web 应用（本机 Windows）

- 环境要点：CLI 注入的 `node` 是 v22.22.2，仓库要求 Node >=24.9；系统 `C:\Program Files\nodejs\node.exe` 是 v24.14.1。所有 pnpm/dsh 命令需 `export PATH="/c/Program Files/nodejs:$PATH"` 置于最前。
- 仓库 `packageManager: pnpm@11.28.5`；全局 pnpm 11.22.0 在工作区内会尝试从 registry.npmjs.org 拉取匹配版本并无限挂起。已用 `npm i -g pnpm@11.28.5 --registry=https://registry.npmmirror.com` 升级解决。
- registry.npmjs.org 国内直连极慢（单请求 40s+），依赖安装必须走镜像：`pnpm install --registry=https://registry.npmmirror.com`（store 落在 `D:\.pnpm-store\v11`）。
- WorkBuddy CLI 注入的 `node-safe-delete-shim` 会在本轮累计删除 50 次后拦截 pnpm 清理临时文件，导致 `build:artifacts` 失败；用 `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000` 可让构建通过。`dev:web` 的 watcher 还会遇到 genie-trash 超时而卡死，改用 `CODEBUDDY_SAFE_DELETE_ENABLED=0` 直接启动服务。
- `pnpm run start:web` 会先做 verifyDepsBeforeRun 的 install，lefthook postinstall 因残留 `.git/dsh-lefthook-install.lock` 失败；移走锁后手动 `node scripts/install-lefthook.mjs` 即可。
- 最终可用启动方式（产物已由 `build:artifacts` 生成，8 个 gate 全 PASS）：
  `CODEBUDDY_SAFE_DELETE_ENABLED=0 node --import tsx/esm apps/cli/src/bin.ts web --no-open --port 3081`
  日志会打印带 token 的 URL，浏览器必须用该 URL 完成一次性鉴权（303 设置 cookie，直接访问根路径会 401）。
- 仓库根目录无 `.env`，实际调用模型需要 `DEEPSEEK_API_KEY`。
